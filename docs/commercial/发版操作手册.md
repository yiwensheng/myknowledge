## 总览：按顺序做这 8 步

```text
① 确认要发什么、版本号怎么升
② 改仓库里的版本与文案（package.json / iss / changelog / **安装向导文案** / 更新记录）
③ 准备密钥与构建环境（.env、Inno Setup）
④ 构建安装包（build-installer.ps1）
⑤ 检查产物（exe、staging、latest.json）
⑥ 本地/干净机验收（含安装向导亮点文案、默认工作流、笔记保存）
⑦ 上传服务器 yizhi/ 三件套
⑧ 线上验证 +（可选）留档 SHA256 / 提交 git
```

**预计耗时**：首次全量构建约 **30～90 分钟**（pip + npm + PyInstaller + Inno 压缩）；纯重新编译 Inno 约 **20～40 分钟**。

## ① 确认发版范围与版本号

### 1.1 先问清三件事

1. **用户可见的大变化**有哪些？（写入 `changelog.html`）
2. **是否必须重打安装包**？（仅改授权服务器配置 → 不必发版；改客户端/后端 → 须重打）
3. **版本号怎么升**（语义化版本）：

| 情形 | 建议 | 示例 |
|------|------|------|
| 重要能力、安装形态、大量功能 | 次版本（有时也直接主版本策略按团队约定） | `2.1.2` → `2.2.0` |
| 修复 / 热修合集进安装包 | 补丁 | `2.2.0` → `2.2.1` |
| 破坏性不兼容（少见） | 主版本 | `2.x` → `3.0.0` |

### 1.2 本手册约定的「权威版本号」

**以 `electron/package.json` 的 `"version"` 为准。**  
构建脚本读它生成：

- 安装包文件名：`dist\Yizhi-Setup-<version>.exe`
- `latest.json` 里的 `latest_version` / `download_url`

`scripts/installer/YizhiSetup.iss` 里的默认 `MyAppVersion` **也要改成同一版本**（未传 `/D` 覆盖时，以及给人肉阅读用）。

## ② 改仓库：版本与文案（构建前必做）

在仓库根目录 `E:\app\Myknowledge` 操作。下列文件建议**同一发版一次改齐**。

### 2.1 必须同步的版本号

| 文件 | 改什么 | 说明 |
|------|--------|------|
| `electron/package.json` | `"version": "x.y.z"` | **权威版本** |
| `electron/package-lock.json` | 根包 `"version"`（与上面一致的两处） | 可用编辑器搜索 `"name": "myknowledge"` 附近 |
| `scripts/installer/YizhiSetup.iss` | `#define MyAppVersion "x.y.z"` 与 `#define MyAppVersionFour "x.y.z.0"` | 四段文件版本，一般补 `.0` |

### 2.2 用户向更新记录（要上传）

编辑 `docs/commercial/changelog.html`：在靠近顶部（2.x 条目前面）**新增一节**：

```html
  <h2>x.y.z <span class="date">YYYY-MM-DD</span></h2>
  <ul>
    <li><strong>某能力</strong>：用户能感知的一句话说明。</li>
    <!-- 再列 3～8 条要点；避免内部文件名堆砌 -->
  </ul>
```

说明：客户端「关于 → 更新记录」打开的是**服务器上的**此页；不改不上传则用户仍看到旧说明。

### 2.3 开发向更新记录（仓库内）

编辑 `docs/更新记录.md`，在顶部追加一条（时间须为**填写时的真实北京时间**）：

```markdown
#### YYYY-MM-DD HH:mm — 发布 x.y.z（短标题）· 已测试

**改了什么**　…
**为什么改**　…
**涉及文件**　…
**改后效果**　…
**发版**　是 → 本地产物 `Yizhi-Setup-x.y.z.exe`；人工压成 `.zip` 后上传 `yizhi/`：zip、`latest.json`、`changelog.html`（对外链接一律 `.zip`）
```

### 2.4 安装向导文案（构建前必改 · 用户安装时可见）

用户跑安装程序时会看到三处文案，**每次发版必须按本版卖点改写**，与 `changelog.html` 对齐；**勿沿用上版亮点**。改完再跑 `build-installer.ps1`（已打好的 exe 不会自动更新文案）。

| 位置 | 文件 | 用户何时看到 |
|------|------|----------------|
| 欢迎页两段说明 | `scripts/installer/YizhiSetup.iss` → `[CustomMessages]` 的 `WelcomeLabel1` / `WelcomeLabel2` | 安装向导第一屏 |
| 「产品亮点」整页 | `scripts/installer/installer-highlights.txt`（UTF-8 BOM 亦可） | 欢迎页之后的说明页（`InfoBeforeFile`） |
| 解压/复制进度下轮播句 | `YizhiSetup.iss` → `GetInstallQuote`（`case` 各分支） | 安装进度条下方，约数秒轮换 |

写法约定：

1. **标题/首行写清版本号**（如「易知 x.y.z」），避免用户分不清新旧包。  
2. **本版亮点 3～6 条**用用户语言（与 changelog 同卖点，可更短）；再保留 2～4 条 evergreen（本地优先、试用、开箱即用等）。  
3. 若有平台限制（如仅 Win64），在 `WelcomeLabel2` 或亮点页点明。  
4. 进度轮播句每条 ≤ 约 40 字，口语、可扫读。

### 2.5 更新清单 JSON（构建会覆盖，仍建议先改好看）

文件：`docs/commercial/yizhi-web/latest.json`

```json
{
  "latest_version": "x.y.z",
  "download_url": "https://www.yzwhysxx.cn/yizhi/Yizhi-Setup-x.y.z.zip",
  "release_notes": "易知 x.y.z：一句话卖点（中文）"
}
```

说明：

- **构建产物**仍是 `dist\Yizhi-Setup-x.y.z.exe`；**用户下载 URL 必须是 `.zip`**（人工把 exe 压成同名 zip 再上传）。
- `changelog.html` 导航与当前版本下载链也须 `.zip`。
- `build-portable.ps1` / 安装构建流程里会**再生成**一份，`release_notes` 有时只写成「易知 x.y.z」。  
  **构建结束后请打开文件确认**；若过简，手动改回完整说明后再上传。

### 2.6 本步自检

```powershell
cd E:\app\Myknowledge
# 应与准备发布的版本一致
(Get-Content .\electron\package.json -Raw | ConvertFrom-Json).version

Select-String -Path .\scripts\installer\YizhiSetup.iss -Pattern 'WelcomeLabel1|GetInstallQuote' -Context 0,12
```

## ③ 准备密钥与环境

### 3.1 开发机一次性环境（未装则装）

| 依赖 | 用途 | 如何装 |
|------|------|--------|
| Python 3.10+（系统安装，**非 venv 当打包源**） | 拷贝进安装包 / 打后端二进制 | 官方安装包 |
| Node.js 18+ | Electron | 官方 / winget |
| ImageMagick | 生成多尺寸 `.ico` | `winget install ImageMagick.ImageMagick` |
| Inno Setup 6 | 编译 Setup exe | `winget install --id JRSoftware.InnoSetup -e` |
| PyInstaller（打后端二进制时） | `runtime\yizhi-backend.exe` | 一般在系统 Python site-packages；见 [后端二进制化.md](后端二进制化.md) |

ISCC 常见路径：`C:\Program Files (x86)\Inno Setup 6\ISCC.exe`

### 3.2 密钥从哪里取（勿提交 git）

| 用途 | 推荐来源 |
|------|----------|
| JWT（安装包注入） | 项目根 `.env` 的 `MYKNOWLEDGE_LICENSE_JWT_SECRET`，**须与** `license-server` 一致 |
| LicenseServer | 固定 `https://www.yzwhysxx.cn/license`（或 `.env` 中 `MYKNOWLEDGE_LICENSE_SERVER`） |
| 大模型 / RAG | 开发机根目录 `.env`（构建会注入用户包 `.env.user`，设置页隐藏） |

**禁止**打进安装包：`license-server\.env`、虎皮椒密钥、Admin Key、个人 wiki 数据。

查看 JWT 是否已配置（不打印具体值）：

```powershell
cd E:\app\Myknowledge
Select-String -Path .\.env -Pattern '^MYKNOWLEDGE_LICENSE_JWT_SECRET=' | ForEach-Object {
  if ($_.Line -match '=\s*\S+') { 'JWT: 已设置' } else { 'JWT: 空' }
}
```

### 3.3（可选）授权预检

## ④ 构建安装包

### 4.1 推荐：一次完整构建

在 **PowerShell 5.1+** 中：

```powershell
cd E:\app\Myknowledge

# （建议）先确认 Electron / vendor 完整
.\scripts\build-electron.ps1

# 从 .env 读 JWT，避免命令行里贴密钥
$jwt = ""
$server = "https://www.yzwhysxx.cn/license"
Get-Content .\.env | ForEach-Object {
  if ($_ -match '^\s*MYKNOWLEDGE_LICENSE_JWT_SECRET=(.*)$') {
    $jwt = $Matches[1].Trim().Trim('"').Trim("'")
  }
  if ($_ -match '^\s*MYKNOWLEDGE_LICENSE_SERVER=(.*)$') {
    $server = $Matches[1].Trim().Trim('"').Trim("'")
  }
}
if (-not $jwt) { throw "请先在 .env 配置 MYKNOWLEDGE_LICENSE_JWT_SECRET" }

.\scripts\build-installer.ps1 `
  -LicenseServer $server `
  -JwtSecret $jwt
```

说明：

- 脚本会新建 `dist\Yizhi-Staging-<version>-<时间戳>\`
- **默认**打 `runtime\yizhi-backend.exe`（耗时）
- 若只需纯 Python 包：加 `-SkipBackendBinary`（不推荐作正式发版）
- PowerShell 脚本请保持 **UTF-8 带 BOM**，否则中文 Windows 下可能解析失败（构建脚本仓库侧已按此处理；若你自写脚本也要注意）

### 4.2 仅重编 Inno（staging 已齐全时）

例如 VC++ Redist 下完了、staging 已含 `runtime\yizhi-backend.exe`，只差 Setup：

```powershell
cd E:\app\Myknowledge
$stage = "E:\app\Myknowledge\dist\Yizhi-Staging-x.y.z-时间戳"   # 换成真实目录名
# $jwt / $server 同上一段读取 .env

.\scripts\build-installer.ps1 `
  -LicenseServer $server `
  -JwtSecret $jwt `
  -StagingDir $stage `
  -SkipPortableBuild `
  -SkipVCRedistDownload
```

前置：`$stage\redist\vc_redist.x64.exe` 已存在（可用 curl 下载到该路径）：

```powershell
$dest = Join-Path $stage "redist\vc_redist.x64.exe"
New-Item -ItemType Directory -Path (Split-Path $dest) -Force | Out-Null
curl.exe -fsSL --retry 5 -o $dest "https://aka.ms/vs/17/release/vc_redist.x64.exe"
```

### 4.3 构建过程中脚本在做什么（便于判断是否卡死）

1. 生成图标 → 复制/安装 Python → pip 装 `requirements-runtime.txt`
2. 同步 Electron / vendor → 拷 skills、prompts、工具链
3. （默认）PyInstaller → `runtime\yizhi-backend.exe`
4. 空 wiki + 注入 `.env.user` → 写 `latest.json`
5. prune 体积 → 下载 VC++ Redist → ISCC 压缩出 Setup

**正常现象**：某阶段长时间无新输出（pip、PyInstaller 分析、Inno 压缩）；请耐心等待，勿强杀除非确认进程不在。

## ⑤ 检查产物

### 5.1 必有文件

```powershell
$ver = (Get-Content E:\app\Myknowledge\electron\package.json -Raw | ConvertFrom-Json).version

Get-Item $exe | Format-List FullName, Length, LastWriteTime
# 体积参考：2.2.0 约 440MB（含后端二进制）；明显偏小（如几十 MB）往往是未打完整运行时
```

### 5.2 Staging 门禁（打开最近一次 staging）

在 `dist\Yizhi-Staging-<ver>-*` 中确认：

| 路径 | 期望 |
|------|------|
| `runtime\yizhi-backend.exe` | 存在（正式发版） |

| `electron\node_modules\electron\dist\electron.exe` | 存在 |

| `redist\vc_redist.x64.exe` | 存在 |

打开 `docs\commercial\yizhi-web\latest.json`：

- `latest_version` = 本次版本  
- `download_url` 指向 `https://www.yzwhysxx.cn/yizhi/Yizhi-Setup-<version>.zip`（对外必须是 zip；本地构建产物仍是 exe）

## ⑥ 本地验收（上传前）

至少在本机或干净 VM 安装 `Yizhi-Setup-<version>.exe` 后检查：

| # | 检查项 | 通过标准 |
|---|--------|----------|
| 1 | 安装向导 | 中文；欢迎页/亮点页/进度轮播文案含**本版**卖点（非上版旧文）；可选桌面快捷方式 / 开机自启 |
| 2 | 启动 | 无控制台黑窗；能进主界面 / 试用提示 |
| 3 | 关于 | 版本号为本次 `x.y.z` |
| 4 | 导入资料 → 工作流 | **有**内置卡片（整理待处理、更新检索库等），不是「暂无工作流」 |
| 5 | 笔记编辑 → 保存 | 出现「保存中…」或 Toast「笔记已保存」；刷新后内容仍在 |
| 6 | 闪念 | 能保存；不误报空内容 |
| 7 | 授权 | 试用/订阅流程正常（细节见 T1～T8） |

静默安装示例：

```powershell
.\dist\Yizhi-Setup-x.y.z.exe /VERYSILENT /SUPPRESSMSGBOXES /NORESTART
```

安装目录默认：`C:\Program Files\Yizhi\`  
用户数据：`%LOCALAPPDATA%\Yizhi\`

## ⑦ 上传服务器

### 7.1 上传哪三个文件（最少）

与现有购买页 **同一 IIS 站点目录**（URL 前缀 `https://www.yzwhysxx.cn/yizhi/`）：

| 本地路径 | 服务器文件名 | 作用 |
|----------|--------------|------|
| `dist\Yizhi-Setup-<version>.exe` → **人工压 zip** | `Yizhi-Setup-<version>.zip` | 用户下载（解压后得安装 exe） |
| `docs\commercial\yizhi-web\latest.json` | `latest.json` | 「检查更新」读此文件 |
| `docs\commercial\changelog.html` | `changelog.html` | 「关于 → 更新记录」 |

**说明：**

- `latest.json` / `changelog.html` 里的下载链必须是 **`.zip`**，且与实际上传的 zip 文件名一致。  
- 构建仍产出 `.exe`；**不要**把对外 `download_url` 指回 `.exe`。  
- 旧版包可留在同目录，互不覆盖；**只改 `latest.json` 就能切换「推荐最新版」**。  
- 上传方式按你们运维习惯任选其一（远程桌面拷贝、共享盘、FTP/SFTP、IIS 管理器等）。物理路径以服务器上 `purchase.html` 所在文件夹为准（该目录即 `yizhi/`）。

### 7.2 上传操作建议顺序

1. 先把 exe **压成 zip**，再传 **zip**（体积大，传完再动入口 JSON，避免短暂时间内新 JSON 指向尚不存在的文件）  
2. 再传 **`changelog.html`**  
3. 最后覆盖 **`latest.json`**（用户检查更新立刻指向新包）

### 7.3 不要上传

- 整个 `dist\Yizhi-Staging-*`  
- 开发机 `.env` / `license-server\.env`  
- 未脱敏的调试日志

## ⑧ 线上验证与收尾

### 8.1 立刻验证

```powershell
# 应返回新版本号与 download_url
curl.exe -s https://www.yzwhysxx.cn/yizhi/latest.json

# 应 HTTP 200，且 Content-Length 接近本地 exe 大小
curl.exe -sI https://www.yzwhysxx.cn/yizhi/Yizhi-Setup-x.y.z.zip

# 更新记录页能打开
curl.exe -sI https://www.yzwhysxx.cn/yizhi/changelog.html
```

浏览器：打开 `https://www.yzwhysxx.cn/yizhi/latest.json` 肉眼确认。

已装旧版客户端：**关于 → 检查更新** → 应提示有新版本并可「前往下载」。

### 8.2（可选）git 提交

仅在你明确要求提交时再 commit。建议包含：

- 版本号相关文件、`changelog.html`、`latest.json`、`docs/更新记录.md`
- **不要**提交 `.env`、密钥、`dist\*.exe`（若仓库未忽略 exe，勿 add）

### 8.3 发版完成后勾选清单

- [ ] `electron/package.json` 版本 = 本次版本  
- [ ] `dist\Yizhi-Setup-<version>.exe` 已生成且体积正常  
- [ ] staging 含 `runtime\yizhi-backend.exe` 与 `skills\`  
- [ ] 本机/VM 验收表（§⑥）通过  
- [ ] 服务器已上传 zip + `latest.json` + `changelog.html`（链接为 `.zip`）  
- [ ] `curl latest.json` 已是新版本  
- [ ] `docs/更新记录.md` 已写发版条目

## 附录 A：热修 vs 正式发版

| 场景 | 做法 |
|------|------|
| 正式对全体用户发版 | 按本手册 ①～⑧ 完整走；**必须**换版本号并上传新 Setup |
| 仅修本机已装的 2.2.0 | 管理员运行例如 `.\scripts\hotpatch-install-2.2.0.ps1`（拷贝前端/`runtime`）；**不**改 `latest.json`，其他用户拿不到修复 |
| 热修要给所有人 | 升补丁号（如 `2.2.1`），重新打包装并上传 |

## 附录 B：常见失败与处理

| 现象 | 可能原因 | 处理 |
|------|----------|------|
| `build-installer.ps1` 解析报错（乱码、缺 `}`） | 脚本 UTF-8 无 BOM，系统按系统代码页解析 | 以 UTF-8 **带 BOM** 保存该 ps1 |
| ensurepip/pip 的 WARNING 导致脚本中止 | `$ErrorActionPreference=Stop` 把 stderr 当错误 | 使用当前仓库已修过的 `build-portable.ps1`；不要手改回旧流水线 |
| VC++ Redist 下载 EOF | `Invoke-WebRequest` 不稳 | 用 `curl.exe -L` 下到 staging `redist\`，再 `-SkipPortableBuild` |
| 安装后「暂无工作流」 | 冻结后端 ROOT 指错 / 缺 `skills\` | 确认包内有 `skills\`；升级含 `lib/config.py` ROOT 修复的版本（见更新记录 2026-07-16） |
| 笔记点保存「没反应」 | 旧版保存走全库 `sync_all` 阻塞 | 使用含增量索引修复的版本；或打补丁包 |
| Setup 体积异常小 | staging 不完整或 Inno 源目录错 | 重新完整 `build-installer`，核对 `-StagingDir` |
| 检查更新仍是旧版 | 未覆盖服务器 `latest.json` 或 CDN/浏览器缓存 | 再 curl；强刷；确认上传路径即 `yizhi/` |
