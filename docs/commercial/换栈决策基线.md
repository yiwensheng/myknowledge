# 易知桌面版 · 换栈决策基线

> **性质**：决策记录（不实施换栈代码）。依据可行性分析与 2.3.0 安装包实测。  
> **版本锚点**：安装包约 **462 MB**；staging 约 **1.5 GB**（Electron + 双 Python + ffmpeg/bun + file-viewer）。

## 已拍板方向（默认）

| 优先级 | 决策 | 说明 |
|--------|------|------|
| **P0** | **方案 A：不换栈，先瘦身** | 去重 Python、可选工具外置/按需、预览降级、启动体感 |
| **P1** | **方案 A+B：Tauri 2 壳 + 保留 Python 后端** | 仅在 A 做到阶段性收益后，或明确要求「更轻桌面壳」时启动 |
| **不做（现阶段）** | 方案 C 全量 C# UI | 不为缩小安装包单独押注 .NET |
| **不做（现阶段）** | 方案 D Rust 全栈重写 | 业务面过广；性价比低于 A/B |
| **延后** | 方案 E 局部 Rust 加速模块 | 待有实测热点（大库索引/扫描）后再议 |

**业务内核**：继续 **Python FastAPI**（`runtime\yizhi-backend.exe` / 开发态 `python -m backend`）。  
**RAG**：继续远程 Embedding API + SQLite FTS5；不因换栈引入本地大模型体积。

## 目标对齐

| 目标 | 主路径 | 预期量级（粗估） |
|------|--------|------------------|
| 安装包更小 | A → 必要时 B | A 后瞄准 **~200～300 MB**；A+B 乐观 **~150～250 MB**（视可选工具是否外置） |
| 启动更顺 | A 启动 UX + 单后端路径；B 轻壳 | 减少 Electron 冷启与双 Python 探测开销 |
| 问答/写作更快 | **不**靠换语言 | 瓶颈在远程 LLM；另案优化 |

## 明确不做的事（本基线有效期内）

- 用 Rust/C# 重写 `lib/` RAG、入库、记忆、授权、播客等业务。
- 在未完成 A 关键去重/外置前，单独开全量 D。
- 为「换栈」破坏：wiki 目录约定、REST API 形状、授权协议、Markdown frontmatter。
