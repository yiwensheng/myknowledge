# 易知 · 订阅服务闭环（P0/P1/P2）设计

> **日期**：2026-08-13（修订：教师六步 + OPC + 职场）  
> **灵感**：[头条 · 先别卖功能，要设计服务闭环](https://www.toutiao.com/article/7672975767529177646/)  
> **目标**：试用期内形成「输入→交付→确认→沉淀」习惯，到期时看见资产，从而愿意订阅。  
> **原则**：不堆功能；不承诺涨粉/提分/成交；未确认资料不编造。

---

## 1. 范围与非目标

| 做 | 不做 |
|----|------|
| P0 首启 10 分钟闭环（Key 测通 + 任务条） | 官方赠送大模型额度 / 代配 Key |
| P1 试用四周剧本 + 到期资产续费页 | 改定价、改授权协议 |
| P2 五个垂直场景模板（见下） | 全自动发布、广告投放、CRM |
| 进度落盘 wiki `.config/service-loop.json` | 云端同步进度 |

---

## 2. 数据模型

路径：`{wiki_root}/.config/service-loop.json`

```json
{
  "version": 1,
  "started_at": "2026-08-13T02:00:00Z",
  "scenario": null,
  "tasks": {
    "key_ok": false,
    "ingest_or_note": false,
    "ask_with_cite": false,
    "distill_once": false
  },
  "weeks": {
    "w1": { "done": false, "note": "" },
    "w2": { "done": false, "note": "" },
    "w3": { "done": false, "note": "" },
    "w4": { "done": false, "note": "" }
  },
  "dismissed_bar": false,
  "template_runs": []
}
```

- 任务完成可由前端显式上报，或由后端根据已有信号推断。
- 初始化清零（`wiki_reset`）时删除该文件。

---

## 3. P0 · 首启闭环（10 分钟）

- `POST /api/llm/probe`：短 chat 测通，返回 `{ok, latency_ms, error}`。
- 设置「大模型」页「测试连接」；任务条四步：Key → 入库/笔记 → 有出处提问 → 蒸馏（可选）。
- 无 Key 不阻断浏览与入库。

---

## 4. P1 · 四周剧本 + 到期资产

| 周 | 标题 | 交付物 |
|----|------|--------|
| W1 | 入库 | ≥1 份可读内容 |
| W2 | 有据问答 | ≥1 次带出处回答 |
| W3 | 一篇产出 | 定稿或模板写入的文稿 |
| W4 | 沉淀 | ≥1 Skill/Principle |

到期/剩余≤7 天：`license-overlay` 展示本地资产数字。

---

## 5. P2 · 垂直场景模板（×5）

入口：写文章旁 / 任务条「场景模板」。

| ID | 场景 | 闭环 | 主要输入 | 输出（预览→确认入库） |
|----|------|------|----------|------------------------|
| `jiaoshi` | **教师课堂** | **备课→上课→练习→作业→检测→反馈** | 学科/年级、本课目标、已有讲义线索、学情（可选）、待确认项 | 六段式教案+练习作业检测与反馈要点；未知标「待确认」 |
| `kaoyan` | 考研/教研 | 讲义入库→错题/考点问答→一页复习稿 | 科目、本周范围、错题/考点笔记、待确认考点 | 一页复习稿 + 建议提问清单 |
| `zimeiti` | 自媒体 | 素材入库→热点稿→蒸馏写作 Skill | 选题、素材、渠道、上期反馈 | 热点稿草案（非终稿）；提示可再蒸馏 |
| `zhichang` | 职场 | 会议纪要入库→待办摘要→周报草稿 | 会议要点/纪要、本周目标、待确认事项 | 待办摘要 + 周报草稿 |
| `opc` | **一人公司 OPC** | 线索/客户笔记→本周交付清单→复盘纪要 | 业务定位、本周客户/线索、交付物、待确认报价/范围 | 一周运营协作草案（清单+复盘）；不承诺成交 |

系统提示强制：不编造未提供事实、不承诺效果数字、未知列待确认。确认后写入 `notes/`。

### 教师六步特别要求（`jiaoshi`）

输出必须含独立小节：备课要点、上课流程、课堂练习、课后作业、检测方式、反馈与下节衔接；缺信息不得虚构课标/学时，标待确认。

## 6. API

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/service-loop` | 状态（含推断合并后的 tasks、weeks、assets 摘要） |
| PATCH | `/api/service-loop` | 更新 tasks/weeks/dismissed_bar/scenario |
| GET | `/api/service-loop/assets` | 资产统计 |
| GET | `/api/service-loop/templates` | 模板列表与字段 |
| POST | `/api/service-loop/templates/{id}/run` | 生成草案 |
| POST | `/api/service-loop/templates/{id}/commit` | 确认写入笔记 |
| POST | `/api/llm/probe` | Key 测通 |

---

## 7. 实现顺序

P0 → P1 → P2；每期 pytest + 更新记录。不默认升版。
