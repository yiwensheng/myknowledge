一、你的资料，正在沉睡
你大约也有过这样的深夜：三个文件夹、两个笔记软件、一整屏聊天窗口，你要找的那份材料明明存过，此刻偏偏如石沉大海，翻遍硬盘也捞不动它。
几百份 PDF，几十个 PPT，一堆会议纪要和网页收藏——标签打了又乱，乱了又打，末了连自己都忘了当初归在哪一类下面。你急了，把关键词丢给大模型，它倒是答得头头是道，语气笃定得很，仿佛世间万事皆了然于胸。你差点就信了——直到你打开原件核对，才发现它把两个项目的结论拧成了一段，还替你「总结」出一条从未存在过的论据。
没有出处的聪明，不过是幻觉；有出处的沉默，方才是诚实。
我们缺少的，从来不是更会说话的模型，而是一个肯替我们把已有之物讲清楚、串起来、再从旧料里生出新的念头来的东西——不是要它替我们决定世界长什么样，而是要它从我们亲手搬回来的砖瓦里，帮我们照见那些被灰尘遮住的纹路。

二、易知是什么
易知，自我进化个人知识库。它绑的是你自己的资料，吃的是你硬盘里的粮食，不是互联网的残羹。你把文件扔进去，它替你切、替你分、替你建索引生向量；你来问，它先翻你的文件，翻到了才开口，还要告诉你第几页第几行；翻不到，它宁可闭嘴。
然而易知做的不止于此。它还要让沉睡的资料生出新的枝叶——你问出来的好答案，写出来的好稿子，经你确认之后，都归档案卷，越积越厚。昨日的材料化作明日思考的起点，此之谓「自我进化」：不是模型变得多大了，是你自己的知识库，在日复一日的翻检与书写之中，长了肉、生了根。
易知还能推演。你给它一个方向，它便从库中翻出所有相关的证据，把已知的事实铺开，把可能的走向逐条列出来，每一条都注明依据的强弱——强据说得笃定，弱据说得谨慎，没有依据的，它干脆不写。它还会老老实实告诉你：库里的货还缺什么，缺的正是你判断所需的拼图。
进得来 · 搜得到 · 答有据 · 推有度 · 越用越聪明

三、它能做什么
其一：千般格式，一室而收
PDF、Word、PPT、Excel、TXT、Markdown、PNG、JPG、MP3、MP4，乃至一条网页链接——凡你能攒下的东西，拖进 inbox 便是。文本提取、自动分类、索引和向量分块，一气呵成，用不着你挨个打开、复制粘贴。网页链接也可以直接入库，正文自动抓取、去重、本地化存档，该留的全留下。
你若在别处已有成体系的资料文件夹，也不必搬移，只消指定外联目录——文件留在原处，易知只读不写不动，而内容已然纳入检索，随时随地可以追问。
其二：混合检索，答必有据
你问它的时候，它走的是混合检索的路子：关键词抓专有名词，Embedding 向量抓换种说法的同款意思，FTS5 全文索引与 RRF 融合排序齐头并进。回答只引库内片段，脚下踏着的每一寸土地，都有出处——脚注标明来源与页码，点击便跳到 PDF 原文对应的那一页。
库内无相关内容时，它绝不肯胡乱编造，只老老实实回你一句：「知识库中暂无足够信息，无法基于库内事实回答该问题。」
你若要核对口径，可以勾选限定资料范围，让检索只在那几份文件里翻找，心里便踏实了。连续对话是默认开启的，追问「展开第二点」，它记得住上文；它还会自动检索你过去问过、写过、确认过的答案——不仅翻旧 PDF，还能翻出你上次亲口认可的那条结论。
其三：推演——从已知望向未知
问答是回答「是什么」，推演是探问「会怎样」。你在「推演」Tab 里输入一个关键词，譬如「台风路径」，再附上一句预测说明，譬如「基于库内资料，未来两周可能如何」，还可以勾选限定资料范围——与提问页同一套逻辑，只搜你指定的那几份文件。
推演只从本地取材：wiki 正文、assets 原文件、RAG 片段、外联目录、DocuBrowser、memory 历史问答——凡库中所有，皆可征引；库外之物，一概不取。它不访问互联网，不调用外部知识库，不依赖任何云端服务。铁证如山方能发论，此推演之所以不虚也。
推演产出一篇预测报告，分四层：
•  已知事实——引用库内片段，逐条标注出处
•  可能走向——列出二至四条，每条标注依据强度：强据则言确，中据则言似，弱据则言或，无据则不书
•  关键不确定因素——坦白承认哪些环节尚在暗处
•  库内缺口——明示还缺什么资料，方能推断更准
推演不是算命。它是从你有的一手证据出发，老老实实地往远处看一眼，同时告诉你：哪里看得清，哪里看不清，哪里压根就是黑的。
推演结果可以保存为笔记归入 notes/，也可以导出留档。日后新资料入库、旧推演有了新的旁证，你不妨再做一次，看看那几条走向的依据强度，是不是变了。
其四：从读到写，一条路走到底
给一个主题，易知从库里拽出相关片段，按体例往外生发——综述、教程、对比、播客稿，随你选。字一行行流出来，像有人坐在你旁边，翻着参考书念给你听。改完存回知识库，导出 Word，都顺手。
最叫人眼前一亮的，是播客体例：对话稿生成之后，TTS 双音色合成——主持人一个声，嘉宾一个声——输出一条完整的音频。读资料、写稿子、念出来，自始至终不出这一个窗口。
其五：自我进化，越用越厚
有人问：「自我进化」是不是一句广告词？
不是。是你用得越多，库里的东西越多；库里东西越多，答得便越有你的滋味。说到底，不过是四条朴素的道理：
•  你问了一个好问题，得到有依据的回答，系统自动将这份问答归入笔记
•  下次搜同类问题，除了旧 PDF，还能翻出你上次确认过的答案
•  你写了一篇综述并存回库中，再写同类主题时，综述本身便成了参考源
•  后台 Loop 巡检发现 inbox 有未处理文件、RAG 有空白区，自行提醒甚至自动入库
用得越久，越不像在问一个陌生的机器，越像在翻自己那部越写越厚的活书——活书之所以活，是因为每一页都有你走过的痕迹。
其六：图形界面与命令行，各取所需
双击「启动易知.bat」，图形界面便起来了——提问、查询、推演、导入、写文章、设置人设，全在窗口里操作，用不着碰一行代码。命令行的老手，则可以直接 yws ask、yws ingest、yws produce，亦可接入 Cursor Agent、纳入脚本自动化。两套入口共用同一套索引与配置，行的是同一条路，只不过有人坐车，有人走路罢了。
其七：Obsidian 协同与 Skills 扩展
知识库目录便是 Obsidian vault，你用 Obsidian 编辑 Markdown，改完 yws index 刷新 RAG，两边的笔记永远通着气。易知也接纳 Cursor Skills 格式的可扩展工作流，内置 wiki-ingest、wiki-ask 等六个 Skill，你也可以自己添——规矩是你定的，工具不过是手脚的延伸。

五、谁在用它，怎么用
研究者与写作者
案头堆了几百篇论文和笔记，易知替你从散落篇什中检出关键段落、生成文献综述、归档写稿心得。下次再写同类主题，前番的综述本身便是一件可引的来源——旧砖不废，新墙自起。
教师与教研人员
政策文件、教研笔记、试卷分析，尽数入库。提问时限定资料，核对表述是否矛盾，十分钟后便可回电话：有，矛盾在此处，以某页某段为准。推演功能尤适教研预判——基于本学期历次检测数据，下一个阶段哪些班级哪些学科可能下滑，先有一张底牌在手。写分享稿、做播客预习材料，亦不出此门。
项目经理与顾问
周报、会议纪要、技术文档批量入库，需要时提问，脚注直达原文页码。推演则帮你从已有数据出发，预判项目走向、关键风险与信息缺口，不必再凭直觉拍板。
程序员与技术人
技术文档、API 说明、博客文章，用 URL 或文件入库。CLI 集成到工作流之中，Cursor Agent 直接调用 yws 命令，自动 ingest、自动 index、Loop 巡检不休——机器替你守夜，你只管白日的营生。

六、推演：从手里的事实望出去
推演这件事，古人说得朴素：「审其已知，推其未至。」易知的推演，正是这个路数——它不是占卜，也不是猜测，而是从你手里已有的证据出发，老老实实地往远处看一眼。
你在「推演」Tab 里填一个关键词，譬如「台风路径」或「某政策」，再补上一句说明，譬如「基于库内资料，未来两周可能怎样」。你还可以勾选限定资料范围，只让它去翻那几份文件。
推演取材，只认本地：wiki 正文、assets 原文件、RAG 切片、外联目录、DocuBrowser 文档、memory 中留存的往日问答——凡库中所有，皆在征引之列。它不访问互联网，不调用 Zep，不运行 OASIS，铁门紧闭，外物不入。
产出的预测报告分四层：
•  已知事实——引用库内片段，逐条注明出处与页码，有几分证据说几分话
•  可能走向——列出二至四条，每一条都标注依据强度：强据则言确，中据则言似，弱据则言或，无据则不书
•  关键不确定因素——哪些环节尚在暗处，坦白承认，绝不遮掩
•  库内缺口——还缺什么资料才能推得更准，缺的东西正是你下一步该去搬的砖
推演的要义不在于猜得准不准，而在于让你看见：哪些是你看得清的，哪些是你看不清的，哪些压根就是黑的。
推演结果可保存为笔记，归入 notes/，亦可以导出留档。待到新资料入库、旧推演有了新的旁证，你不妨再做一次，看看那几条走向的依据强度是不是此消彼长——推演不是一锤子买卖，而是一场随着库的生长而不断修正的对话。
知其已知，推其未至；不知其不知，则推亦妄矣

七、越用越聪明，靠的不是魔法
自我进化不是咒语，是日积月累的功夫。你每问一次好问题，库便厚一分；每写一篇好稿子并归档回来，库便深一寸。日子久了，再搜同类的话题，它不仅能翻出旧 PDF 里的原文，还能翻出你上次确认过的问答、你前番写就的综述——那些东西不是死资料，是你这路走过来留下的脚印。
后台的 Loop 巡检也在默默做工：inbox 里有没有还没整理的文件？RAG 里有没有空白区？草稿有没有悬而未决的？它替你盯着，该入库的入库，该索引的索引，不至于让新搬来的砖头堆在门口落灰。
用得越久，越不像在问一个全知全能的神明，越像在翻自己那部越写越厚的活书——活书之所以活，是因为每一页都有你走过的痕迹，而新写的那一页，总是踩在旧页的肩上。

八、上手不难
三步便够：
•  双击「启动易知.bat」——首次自动安装依赖、初始化目录
•  配置 .env，填入 LLM API Key（OpenAI 兼容接口，通义、智谱都行）
•  把文件拖进 inbox，点「整理」，然后开始提问或推演
不配 API Key 也能用：入库、查询、索引，件件使得，只是提问、写文章与推演需调用大模型。本地检索与索引不调大模型，一文不花；API 用多少算多少，账单始终在你自己手里。

九、写在最后
易知是给资料囤积党、被幻觉伤过的人留的一扇后门：
进得来 · 搜得到 · 答有据 · 推有度 · 生发新知 · 写能回库 · 还会自我进化
倘若你也经历过凌晨一点、明明存过却搜不到的烦躁——或者也被「头头是道、对不上原件」的回答坑过——不妨试它一试。
不必把它想成多厉害的物事。就当给自家资料库请了一个不肯乱说话的书记官——它替你翻旧卷，替你找原文，替你从故纸堆里望一眼前路，望完了老老实实告诉你：哪里看得清，哪里看不清。它还替你把问出来的、写出来的、推演出来的，好好种回地里。种得越久，地越肥，它便越有话可说——而那话的根，始终扎在你自己的土里。
