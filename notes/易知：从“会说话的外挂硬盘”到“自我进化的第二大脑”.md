# 易知：从“会说话的外挂硬盘”到“自我进化的第二大脑”

## 节目简介

本期对话基于知识库中关于“易知”（Myknowledge）的多篇核心笔记与产品说明。我们将探讨为何传统的“第二大脑”工具链往往在“存”与“用”之间断裂，以及易知如何通过本地优先、混合检索（RAG）与记忆进化机制，解决“有出处”与“长厚”两大痛点。内容涵盖易知的核心架构、多模态产出（文章、推演、播客）、双模操作界面，以及它与“自己搭一套”方案的本质区别。

## 对话脚本

**主持人**：咱们今天聊聊“易知”。很多人都在找“第二大脑”，但好像大多数工具最后都变成了“会说话的外挂硬盘”。易知想解决的核心问题是什么？

**嘉宾**：对，痛点不在于“不会用 AI”，而在于“用不起来”。你存了一堆 PDF 和网页，问 AI 它给一段通顺漂亮的话，但查无出处，你不敢用。或者答案全对，但散落在十个对话窗口里，库还是空的。易知想做的，是让知识库真正“长厚”，而不是只进不出。

**主持人**：也就是说，它强调“回写”和“进化”？

**嘉宾**：没错。易知的核心价值链条是：资料进库 → 自动索引 → 有依据问答 → 优质内容回写 → 越用越聪明。它把推演、文章、播客、目标任务书等产出接进同一条流水线，让每一次问答都成为库的一部分。

**主持人**：这听起来很理想，但实际操作中，数据怎么进库？支持哪些格式？

**嘉宾**：它支持“统一入库”。PDF、PPT、Excel、Word、Markdown、图片、音视频，甚至网页 URL 都能进。GUI 有导入页，命令行有 `yws ingest`。如果你不想复制文件，还可以用“外联目录”，只读挂进检索，不动原文件。

**主持人**：那检索的时候，它怎么保证“有出处”？

**嘉宾**：它走的是混合检索路线：关键词抓专有名词，Embedding 向量抓同义意思，FTS5 全文索引与 RRF 融合排序。回答只引库内片段，脚注标明来源与页码，点击就能跳到 PDF 原文。库内没相关内容时，它宁可闭嘴，也不瞎编。

**主持人**：我注意到易知有个“推演”功能，这和普通的问答有什么区别？

**嘉宾**：问答是回答“是什么”，推演是探问“会怎样”。它基于本地库推可能走向，结论要求有依据。产出的预测报告分四层：已知事实、可能走向（标注依据强度）、关键不确定因素、库内缺口。这不是占卜，是把“如果继续按这条线走”钉在证据上。

**主持人**：除了问答和推演，易知还能产出什么？

**嘉宾**：它的出口做得很宽。可以写文章（综述、教程、对比等），可以生成播客对话稿并合成双音色音频，还可以用“leader”Skill 把模糊目标焊成可执行的任务书。这些产出都可以直接入库，成为未来的参考源。

**主持人**：听起来功能很全，那它和市面上那些“自己搭一套”的方案，比如 Ollama 加向量库，差在哪？

**嘉宾**：自己拼方案，能跑通 Demo，但维护成本在半年后才露面：分块策略、冲突提示、会话记忆、归档规则、TTS、授权……每一项都可能变成周末加班。易知选择本地优先，数据与索引在你机器上，LLM 走可配置的 OpenAI 兼容接口。你换模型供应商，不必换知识库形态。

**主持人**：也就是说，它把“可控性”交给了用户？

**嘉宾**：对。它不假装“一键替代一切”。人设、输出规则、资料范围、矛盾检测，都是可开关的控制面。专业用户要的是可控，不是黑盒魔法。它至少把“无依据不瞎编”、“冲突要标出来”写进了默认行为。

**主持人**：那对于普通用户，上手难吗？

**嘉宾**：上手不难。双击“启动易知.bat”，首次自动安装依赖、初始化目录。配置 `.env` 填入 API Key 就行。不配 Key 也能用，入库、查询、索引都使得，只是提问和推演需调用大模型。本地检索与索引不调大模型，一文不花。

**主持人**：最后，你觉得易知适合什么样的人？

**嘉宾**：适合个人或小团队，资料以文档/网页为主，要私有、要可复查。已经在用 Markdown 思路，但缺可信问答和回写回路的人。它不适合指望“零配置秒变百科全书”的人。库空着，什么系统都只会礼貌地拒绝你——这反而是好事。

**主持人**：也就是说，你得愿意把材料真正喂进去，并逼自己用“有出处”的标准验收回答？

**嘉宾**：对。库会不会长厚，第二天打开就知道。
