# 易知：第二大脑不缺聊天框，缺的是会进化的知识库

资料越堆越多，问答却越来越飘——这不是模型不够聪明，是工具链断了。
很多人把 Notion 、 Obsidian 、云端 AI 拼成一套「第二大脑」。存得下，搜得到，聊两句也行。真要写报告、推演下一步、把结论落回库里，链条就断。 2026 年个人知识库讨论里， RAG （提问时再检索）和 Karpathy 推动的 LLM Wiki （入库时先编译成结构化笔记）被反复对比；多数人却卡在中间：既没有可信检索，也没有回写进化。
易知（ Myknowledge ）想做的事更硬一点：本地知识库 + 混合检索问答 + 记忆进化，并把推演、文章、播客、目标任务书等产出接进同一条流水线。

## 痛点不是「不会用 AI 」，是「用不起来」

你大概经历过这种循环：
把 PDF 、会议纪要、网页收藏丢进某个文件夹。过两周问 AI 「上季度质量复盘的结论是什么」，它给一段通顺、漂亮、查无出处的话。你不敢用。
或者反过来：答案全对，但散落在十个对话窗口里，库还是空的。下次还得重新喂料。
这太扯了。漂亮答案没有出处，比没有答案更糟——你会信一两天，然后在汇报会上被问穿。
所谓第二大脑，若只会聊天、不会长厚，那只是会说话的外挂硬盘。
行业里常见的本地方案——Ollama 跑模型、 AnythingLLM / Open WebUI 挂 RAG——解决了「私有数据不上云」的焦虑。它们未必解决「优质回答要不要回写」「草稿缺口谁来扫」「产出是不是只剩一种格式」。易知把这些问题当成产品默认路径，而不是留给用户自己用脚本缝合。

## 易知怎么把「存」变成「进化」

按项目报告书的说法，核心价值可以压成一条链：
资料进库 → 自动索引 → 有依据问答 → 优质内容回写 → 越用越聪明。
具体手段并不神秘，但绑在一起才有意义。
**统一入库**。 PDF 、 PPT 、 Excel 、 Word 、 Markdown 、图片、音视频、网页 URL 都能进。 GUI 有导入页， CLI 有 `yws ingest` / `yws url`。外联目录还能只读挂进检索，不必把整盘文件复制进库。
**可信问答**。 默认混合 RAG （关键词 + 向量）。检索没命中库内片段时，系统倾向拒答或标明依据不足，而不是用预训练常识「补全」。脚注能开到原文， PDF 还能跳页。你要的不是更会编，是更敢用。
**记忆与进化**。 「记忆与进化」面板跟踪规则、会话、审计；优质问答可自动归档到笔记； Loop Engineering （`STATE.md` + `yws loop`）会扫 inbox / 草稿缺口。规则、问答、归档三股线变厚，库才像在跟你一起干活，而不是静态仓库。
**双模操作**。 Electron 桌面端给日常；`yws` 命令行给脚本和 Agent 。同一套 Wiki 根目录、同一套 `.env`，不会 GUI 一套、自动化另一套。
说白了：第二大脑要会记、会查、会改口、会把结论写回去。缺任何一环，都是半成品。

## 产出不止文章：推演、播客、 leader

很多知识库产品停在「问完就结束」。易知把出口做宽。
**写文章**。 多体例产出（综述、教程、对比、播客稿等），可定稿入库、导出 Word 。能从现有笔记学语气，也能开「第一性原理与对抗式审查」这类写作约束——用不用你决定，但选项在。
**播客音频**。 播客体例写出对话脚本后，可按主持人/嘉宾双音色做 TTS ，合并成完整音频。适合把复盘变成通勤可听的材料，而不是再开一个录音软件。
**推演**。 基于本地库推可能走向，结论要求有依据，结果可存成笔记；关系图帮你看见假设之间怎么连。这不是占卜，是把「如果继续按这条线走」钉在证据上。
**leader （目标任务书）**。 内置 Skill ：把模糊目标焊成可执行任务书（含防作弊验收）， GUI 工作流或 `yws skill run leader` 都能跑。长任务开工前先写清「什么叫完成」，比空喊「用 AI 提效」有用得多。
Skills / 工作流快捷入口也在：重复动作不必每次从零点。

如果你只是想「多一个能聊的窗口」，这些出口显得多余。如果你要把个人知识库当成工作台，缺了它们，库永远停在输入侧。

## 和「自己搭一套」差在哪

自己拼 Ollama + 向量库 + 笔记软件，能跑通 Demo 。维护成本在半年后才露面：分块策略、冲突提示、会话记忆、归档规则、 TTS 、授权、安装包体积……每一项都可能变成周末加班。
易知选择本地优先：数据与索引在你机器上； LLM / Embedding / TTS 走可配置的 OpenAI 兼容接口。你换模型供应商，不必换知识库形态。
它也不假装「一键替代一切」。人设、输出规则、资料范围、矛盾检测，都是可开关的控制面——专业用户要的是可控，不是黑盒魔法。

我见过太多演示视频：上传三页 PDF ，问一个送分题，全场鼓掌。换你自己那堆互相打架的制度文件试试。易知至少把「无依据不瞎编」「冲突要标出来」写进默认行为；至于你的库乱不乱，还得靠导入纪律和规则沉淀。工具帮得了忙，替不了你整理。

## 谁适合现在就装

•个人或小团队，资料以文档/网页为主，要私有、要可复查。
•已经在用 Markdown / Wiki 思路，但缺可信问答和回写回路。
•需要同一套库同时出文章、推演笔记、播客音频、任务书。
•愿意配 API Key ，接受「本地库 + 云端推理」的分工（敏感原文仍在本地）。
不适合指望「零配置秒变百科全书」的人。库空着，什么系统都只会礼貌地拒绝你——这反而是好事。
启动很直接：双击 `启动易知.bat`，或 `yws gui`。命令行侧 `yws ask` / `yws produce` / `yws skill list` 与 GUI 共用同一库。
第二大脑这个词被用滥了。真正难的不是再接一个模型，而是让知识库会进化，并允许产出长出不同形态。
易知能不能成为你的那套，取决于你是否愿意把材料真正喂进去，并逼自己用「有出处」的标准验收回答。
库会不会长厚，第二天打开就知道。
